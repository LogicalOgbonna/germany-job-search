At Genentech, I was building the frontend for our JWT-based authentication flow when users started experiencing silent session drops. The symptom appeared frontend-side: users were randomly logged out mid-session. My initial assumption was a React state issue, but after tracing the flow through Chrome DevTools Network tab, I noticed the refresh token endpoint was intermittently returning 401s even with valid HTTP-only cookies attached.

I dug into the backend request logs with the backend engineer and discovered the issue: the token refresh endpoint was checking the access token's expiry claim before issuing a new one, but there was a clock skew between the auth service container and the API gateway. Tokens that the frontend correctly identified as expired (triggering the refresh) were sometimes still considered "valid" by the backend, which then rejected the refresh attempt as premature, leaving the user in a dead state with an expired access token and no new refresh.

My contribution was identifying that the failure wasn't a frontend state bug at all, pinpointing the exact failing request pattern from the browser, and proposing the fix: adding a small tolerance window (30 seconds) to the backend's expiry check. The backend engineer implemented the server-side fix, and I updated the frontend's token refresh logic to retry once with a short delay as a defensive fallback. The silent logouts stopped completely after that.

This is a pattern I've repeated across roles. At ActivEdge, I regularly traced issues from our React dashboards back to the settlement API layer, particularly around EventSource connections dropping data during high-volume transaction periods. Being comfortable reading backend logs, understanding API contracts, and reasoning about what's happening on the server side lets me unblock myself and collaborate effectively with backend engineers rather than just filing tickets and waiting.
